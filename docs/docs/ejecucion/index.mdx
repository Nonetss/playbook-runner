Un playbook no se ejecuta tal cual: el ejecutor prepara un directorio temporal, modifica la copia y lanza `ansible-runner` con parámetros fijos. Estas son las reglas que resultan.

<Entities type="reglas" group="area" columns="name,effect,do,checked" />

`probado` significa ejecutado con `ansible-runner` y `ansible-core` 2.21 contra `localhost`, pasando por `retarget_playbook` y `event_payload` reales, el 2026-11-04 (las variables del inventario del repositorio, el 2026-11-05). `leido` significa leído del código. Nada se ha probado contra un host real por SSH.

## Síntomas

| Síntoma | Causa | Qué hacer |
| --- | --- | --- |
| La tarea sale OK y no se ve nada | [`debug` con `var`](catalog:reglas/debug-var-no-se-ve), o un módulo sin `msg` ni `stdout` | Imprimirlo con `debug` y `msg` |
| `Conditional result ... derived from value of type 'str'` | [Variable de tipo Texto](catalog:reglas/extra-vars-texto) usada sin `bool` | Cambiar la fila a Booleano o usar `when: flag \| bool` |
| `'>' not supported between instances of ...` | Variable de tipo Texto usada sin `int` | Cambiar la fila a Número o usar `(n \| int) > 5` |
| La ejecución no avanza ni termina | [`vars_prompt` o `pause` sin `seconds`](catalog:reglas/prompts-se-cuelgan) | Cerrar la pestaña, o esperar a la hora si es un job |
| Una tarea corre como root y debía ser otro usuario | [`become_user` se ignora](catalog:reglas/become-user-ignorado) | `runuser -u usuario --` |
| Una play corre en hosts que no debería | [`hosts` no decide](catalog:reglas/hosts-no-decide) | Un playbook por trabajo, o una condición con `when` |
| `the role 'x' was not found` | Playbook inline, rol de `requirements.yml` o `roles_path` de `ansible.cfg` | [Crear un rol](../guias/crear-rol.mdx) |
| `Attempt to use undecryptable variable` | [`!vault`](catalog:reglas/vault-no) sin la contraseña correcta o en un playbook inline | Poner la contraseña en el repositorio, o secretos de Infisical |
| `Attempting to decrypt but no vault secrets found` | [Fichero de variables cifrado](catalog:reglas/inventario-del-repositorio) en un repositorio sin contraseña | Poner la contraseña en el repositorio |
| Una variable de `group_vars` llega vacía | Su grupo no es `all`, o [`ansible.cfg` no declara el inventario](catalog:reglas/inventario-del-repositorio) | Moverla a `group_vars/all` y declarar `inventory` |
| `Playbook ... is encrypted with Vault` | [Playbook cifrado entero](catalog:reglas/vault-playbook-cifrado) | Cifrar solo sus variables |
| Un cambio subido a Git no se aplica | [Se ejecuta el commit sincronizado](catalog:reglas/git-commit-fijado) | Pulsar **Sincronizar** |
| El fichero no aparece tras sincronizar | [No cumple la detección](catalog:reglas/git-deteccion) | Revisar `hosts`, carpeta y tamaño |

## Salida en la consola

`apps/ansible/app/services/ansible/payload.py` reduce cada evento a `event`, `host`, `play`, `task`, `task_action`, `changed`, `msg`, `stdout`, `stderr` y `rc`. Eso es lo que recibe el navegador y lo que se guarda en `job_runs`. Lo demás se pierde.

Si Ansible falla por el propio playbook, porque no puede cargarlo o descifrar un fichero, y ningún host ha informado de un fallo, `_stream_runner` (`apps/ansible/app/grpc/services/runner.py`) termina con su mensaje como error de la ejecución, que un job guarda en `job_runs.error`. El mensaje puede citar líneas del playbook.

| Tarea | Se ve |
| --- | --- |
| `debug` con `msg` de texto | El texto |
| `debug` con `msg` de tipo lista | JSON en una línea |
| `debug` con `var` | Nada |
| `command` o `shell` | `stdout` y `stderr` |
| Módulos que devuelven otros campos | Nada |
