# Product

## Purpose

Playbook Runner is a self-hosted technical console for operating Ansible
playbooks, inventories, credentials, scripts, and scheduled execution from a
single authenticated interface. It is intended for infrastructure operators
who need repeatable remote operations without exposing SSH material to the
browser or maintaining ad-hoc shell history.

## Operating model

The Astro frontend is the browser entry point. Hono owns authentication and
the typed, versioned public API. The internal Ansible FastAPI service receives
only backend-to-service requests and materializes execution files in its own
runtime. PostgreSQL stores application data and Better Auth state.

The externally consumable contract is versioned beneath `/rpc/v1` and
`/api/v1`. A new API version is additive: existing versions remain available
until a deliberate deprecation change is approved.

## Product principles

1. **Credentials stay server-side.** Private keys never enter browser state or
   a client-visible API response beyond the trusted internal execution path.
2. **Runs are inspectable.** A user can identify what was run, where, and its
   result from the job-run history.
3. **Automation is explicit.** Inventory, playbook, schedule, and credential
   selection are typed inputs rather than implicit shell context.
4. **Operational safety precedes convenience.** Authentication, health, and
   structured logs are baseline behavior for every deployed service.

## Constraints

- Bun and Turbo coordinate TypeScript workspaces; `uv` owns the Python
  service environment.
- Database schema changes require a user-managed Drizzle migration and are
  never generated by automated repository tasks.
- Docker Compose readiness is meaningful only when all dependent services
  provide health endpoints.
